企业级 RAG 架构落地指南

RAG（检索增强生成）用于将企业私有知识引入大模型回答流程，目标是提升准确性、可解释性与时效性。

1. 基础链路

  1. 文档处理：解析 PDF/网页/工单，统一清洗结构。
  2. 分块切分：按语义段落切 chunk，附带来源元数据。
  3. 向量化存储：写入向量数据库，支持 ANN 检索。
  4. 在线检索：根据问题召回 top-k 片段并重排。
  5. 回答生成：模型仅基于检索上下文输出并附引用。

2. 降低“幻觉”的关键手段

  • 提示词中加入“不得超出资料回答”的硬约束。
  • 为每段上下文保留来源 URL、文档版本、更新时间。
  • 使用 reranker 对召回结果二次排序，提高相关性。
  • 对低置信度问题返回“需要人工确认”。

3. 评估体系

不能只看主观体验，应建设离线评测集：包含事实问答、流程问答、时效问题与拒答样例。常见指标包括命中率、引用正确率、回答完整度、拒答准确率。

4. 生产化建议

  • 设计增量更新机制，文档变更后自动重建索引。
  • 对敏感数据做访问控制与脱敏处理。
  • 全链路可观测：记录 query、检索片段、模型输出、用户反馈。
  • 建立反馈闭环：坏答案进入标注池，定期优化分块与提示模板。
